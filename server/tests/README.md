# Юнит-тесты косметологического центра SKIN CODE

## 📋 Обзор

Создано **15 юнит-тестов** для двух ключевых модулей приложения:
1. **AI модуль** - анализ противопоказаний препаратов
2. **Master модуль** - панель мастера (управление клиентами, рекомендациями, назначениями)

## 🧪 Список тестов

### AI модуль (4 теста):
1. **Возвращает 400 при отсутствии drugName** - проверка валидации входных данных
2. **Успешно обрабатывает запрос без userId** - базовый сценарий работы ИИ
3. **Запрашивает данные пользователя при наличии userId** - интеграция с профилем клиента
4. **Обрабатывает ошибку OpenAI API** - обработка исключений внешнего сервиса

### Master модуль (11 тестов):
5. **Возвращает список клиентов специалиста** - получение данных из БД
6. **Возвращает пустой массив при ошибке БД** - обработка ошибок базы данных
7. **Возвращает полную информацию о клиенте** - комплексный запрос данных
8. **Возвращает null для профиля если его нет** - обработка отсутствующих данных
9. **Создает рекомендацию** - CRUD операция создания
10. **Обрабатывает ошибку при создании рекомендации** - обработка исключений
11. **Создает назначение препарата** - работа с назначениями
12. **Обрабатывает ошибку БД при создании назначения** - обработка ошибок
13. **Возвращает назначенные препараты** - получение списка назначений
14. **Возвращает пустой массив при ошибке** - обработка ошибок запроса
15. **Возвращает справочник препаратов** - работа со справочными данными

## 🛠️ Технологии

- **Jest** - фреймворк для тестирования
- **Supertest** - HTTP assertions для тестирования API
- **Моки (Jest)** - изоляция зависимостей через заглушки

## 🔧 Изоляция зависимостей

Использованы **тестовые заглушки (моки)** для:

1. **Базы данных** - функция `query`
2. **OpenAI API** - объект `openai.chat.completions.create`
3. **Моделей Sequelize** - `MedicalRecord`, `PrescribeMedication`

## 🚀 Запуск тестов

### Требования:
- Node.js 16+
- npm

### Установка зависимостей:
```bash
cd server
npm install jest supertest --save-dev
```

### Запуск тестов:
```bash
# Способ 1: Через скрипт
cd server/tests
node run-tests.js

# Способ 2: Через Jest напрямую
cd server
npx jest tests/unit-tests.js

# Способ 3: С измерением покрытия
cd server
npx jest tests/unit-tests.js --coverage
```

## 📊 Измерение покрытия

При запуске с флагом `--coverage` генерируются отчеты:
- **Текстовый отчет** - в консоли
- **HTML отчет** - `coverage/lcov-report/index.html`
- **LCOV файл** - для интеграции с CI/CD

### Ожидаемое покрытие:
- **Строки кода:** 70-80%
- **Функции:** 75-85%
- **Ветви:** 60-70%

## 🎯 Особенности реализации

### 1. **Полная изоляция**
- Тесты не зависят от реальной БД или внешних API
- Контролируемые сценарии ошибок
- Быстрое выполнение

### 2. **Различные типы тестов**
- Позитивные тесты (успешные сценарии)
- Негативные тесты (ошибки и исключения)
- Тесты валидации (проверка входных данных)

### 3. **Проверка исключений**
- HTTP коды ошибок (400, 500)
- Сообщения об ошибках
- Обработка исключений внешних сервисов

### 4. **Измерение покрытия**
- Автоматическая генерация отчетов
- Анализ по категориям (строки, функции, ветви)
- Готовность к интеграции в CI/CD

## 💡 Пример теста

```javascript
test('POST /api/ai/contraindications - должен возвращать 400 при отсутствии drugName', async () => {
  const response = await request(app)
    .post('/api/ai/contraindications')
    .send({ drugDescription: 'Some description' })
    .expect(400);

  expect(response.body.error).toBe('drugName required');
});
```

## 📞 Поддержка

При возникновении проблем:

1. Убедитесь, что установлены зависимости: `jest` и `supertest`
2. Проверьте, что тестовый файл `unit-tests.js` находится в `server/tests/`
3. Запустите тесты по одному для диагностики:
   ```bash
   npx jest tests/unit-tests.js -t "должен возвращать 400"
   ```
